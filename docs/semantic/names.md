# Donabe 名前解決の仕様
## 1. 概要
名前解決とは、プログラム中に記述された識別子が、どの宣言を指しているかを決定する処理である。

本仕様書では、Donabeにおける識別子の宣言とその解決について定義する。
なお、各構文についての詳しい定義は、[構文仕様](../syntax/syntax.md)で定義する。

## 2. 定義
### 2.1 識別子
識別子とは、プログラム中の定数、変数、関数、引数の名前である。命名規則については[構文仕様](../syntax/syntax.md)で定義する。
### 2.2 宣言
宣言とは、新たな識別子を参照可能なものとして定義することである。
`let`文、`var`文、関数定義文、引数名の宣言がこれに当たる。詳しくは、[宣言](#3-宣言)節で説明する。

## 3. 宣言
### 3.1 定数宣言
定数宣言は、`let`文により行う。
例:
```
let nabe = "鍋";
```
### 3.2 変数宣言
変数宣言は、`var`文により行う。
例:
```
var pot = "pot";
```
### 3.3 関数宣言・引数宣言
関数宣言は、関数宣言文により行う。引数宣言は、関数定義文の一部である。
例:
```
func add(a: Int, b: Int) -> Int {...}
```
この場合、引数宣言は`a: Int`と`b: Int`である。

引数を宣言しないことも可能である。
```
func getNum() -> Int {...}
```

## 4. スコープ
### 4.1 グローバルスコープ
グローバルスコープとは、どのブロックにも入っていないスコープである。
このスコープには、`let`文、`var`文、関数定義文のみを記述できる。また、ここで宣言された識別子は、プログラム中のどこからでも参照可能になる。
### 4.2 関数スコープ
関数スコープとは、関数定義、または関数リテラルにより発生するスコープである。
このスコープには、任意の文を記述できる。ここで宣言された識別子は、そのスコープ、またはその内側のスコープからのみ参照が可能である。
また、関数スコープには、その関数の引数が宣言される。これもそのスコープ、またはその内側のスコープからのみ参照可能である。
### 4.3 ブロックスコープ
ブロックスコープとは、関数定義文と関数リテラル以外のブロックを持つ文により発生するスコープである。ブロックの構文については、[ブロック文](../syntax/syntax.md#31-ブロック文)にて定義する。
このスコープには、任意の文を記述できる。ここで宣言された識別子は、そのスコープ、またはその内側のスコープからのみ参照可能である。
### 4.4 前方参照
前方参照とは、ある識別子の宣言時に、後から宣言される識別子を参照することである。
例:
```
let a = b + 10;
let b = 20;
```
この場合、`a`の初期化式で、まだ宣言されていない`b`を参照している。これが前方参照である。

前方参照は、グローバルスコープでのみ可能である。その他のスコープで前方参照を行うことは禁止されている。

## 5. シャドーイング
シャドーイングとは、親スコープで宣言された識別子と同名の識別子を、子スコープで宣言することである。
例:
```
let a = 10;
{
    let a = 20;
    print(a);   //20
}
print(a);   //10
```
この場合、外側スコープの`a`と内側スコープの`a`は、全く異なるものとして扱われる。これがシャドーイングである。

### 5.1 外側スコープの変数の参照
シャドーイングを行うと、同名の外側スコープの識別子を参照することはできなくなる。
> [!TIP]
> この制約を避けるには、シャドーイングを行わず、子スコープで別名変数を宣言すればよい。

### 5.2 同一スコープ内での重複宣言
同じスコープ内で、同じ名前の識別子を複数宣言することは許可されていない。
例:
```
let a = 10;
let a = 20; //エラー
```

## 6. 名前解決
以上のことを踏まえ、名前解決の詳しい手順を定義する。
名前解決が完了した後、コンパイラは識別子を名前ではなくシンボルとして扱う。これにより、名前解決以降の処理では、識別子名を用いた探索を行う必要がなくなる。
### 6.1 名前解決の結果
名前解決の結果は、次の三種類のシンボルのいずれかとなる。そのシンボルが識別子に割り当てられる。
#### 6.1.1 ローカルシンボル
ローカルシンボルは、参照と同じ関数スコープ内に宣言が見つかった場合に割り当てる。
ブロックスコープはコンパイル時に除去されるため、ブロックスコープ内で宣言された識別子もローカルシンボルとして扱う。

このシンボルは、宣言のIDを保持する。
#### 6.1.2 キャプチャシンボル
キャプチャシンボルは、現在のスコープから親のスコープを辿って探索した際、グローバルスコープ以外で宣言が見つかった場合に割り当てる。

このシンボルは、関数スコープを辿った深さと、たどった先の宣言のIDを保持する。
スコープを辿った深さは、自身の関数スコープを0とし、親の関数スコープへ移動するたびに1増える整数である。
関数スコープが異なる場合、同じIDが割り当てられていても、それぞれ異なる識別子として扱う。
#### 6.1.3 グローバルシンボル
グローバルシンボルは、グローバルスコープで宣言が見つかった場合に割り当てる。
このシンボルは、宣言の識別子名を保持する。
### 6.2 グローバルスコープの探索
名前解決を開始したら、まずグローバルスコープで宣言されている全ての識別子を登録する。
その後、グローバルスコープの内容を順に解決していく。
### 6.3 名前解決の探索
名前解決では、参照位置を起点とし、現在のスコープから親のスコープへ順に宣言を探索する。

最初に宣言が見つかったスコープによって、割り当てるシンボルの種類を決定する。
- 現在の関数スコープ内で宣言が見つかった場合、ローカルシンボルを割り当てる。 
- 現在の関数スコープより外側の関数スコープで宣言が見つかった場合、キャプチャシンボルを割り当てる。
- グローバルスコープで宣言が見つかった場合、グローバルシンボルを割り当てる。
- いずれのスコープにも宣言が見つからなかった場合、即座にコンパイルエラーとする。
探索は、最も内側のスコープから行う。そのため、シャドーイングされている識別子は、最も内側にある宣言が割り当てられる。
### 6.4 名前解決後の識別子
名前解決が完了すると、各識別子は対応するシンボルによって表される。
ローカルシンボルは宣言IDのみを保持するため、同じ関数スコープ内の識別子をIDによって直接識別できる。
キャプチャシンボルは、関数スコープを辿った深さと宣言IDによって、外側の関数スコープに存在する識別子を識別する。
グローバルシンボルは識別子名によってグローバルスコープの宣言を識別する。
このため、名前解決以降のコンパイル処理では、識別子名を用いた探索を行う必要がない。例えば、型解析ではスコープごとの型情報を次のような構造で管理できる。
```java
List<Map<ID, Type>>
```
各要素は関数スコープごとの型情報を表し、`ID`からその識別子の型を取得する。

キャプチャされた識別子については、キャプチャシンボルが保持する関数スコープの深さを利用して、外側の関数スコープにある型情報を参照する。
